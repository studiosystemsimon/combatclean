Combat Clean — Hardcoded Values Audit

Static sweep of src/game · src/view · src/controller · src/core for tuning literals, magic multipliers, offsets, and hacky constants. Excludes src/data (the sanctioned home), dev-only preview/marksman, and vendored packages/bishop.

Project hard rule (CLAUDE.md · "All tuning is data"): every gameplay number, threshold, duration, speed, rate, count, or colour must live in src/data/*.json and be read via the store/config — magic literals in game/view/ui/input are violations. Structural constants (0/1, indices, Math.PI, -1 sentinels, pure drawing primitives) are allowed. SHOULD-BE-DATA = tunable value living in code · HACKY = magic/fudge constant or a value that fights the data layer · STRUCTURAL-OK = allowed, listed for completeness.

Highest-signal findings

  • The entire VFX layer reads zero values from data. There is no vfx.json/store for src/view/fx/** — every duration, multiplier, offset, and colour is inline. Biggest single source of violations (~120).
  • Data layer silently overridden: FxLayer.jsx:154 hardcodes hero-trail width:3, length:6 even though _vfx.json already defines per-chain width/length (7/9, 4/20, 9/9). The value exists in data but is bypassed.
  • Combat-math defaults baked into logic: battle.ts:50/82 || 900 (default hero/enemy attack cadence ms) and battle.ts:220 || 5 (default limit orders-to-charge) — real tuning as inline fallbacks.
  • Genuinely hacky magic: shake/drag decay bases Math.pow(0.0015,dt) / Math.pow(0.10,dt); intro-director.js:131 +44px "moves down then up" glitch-fix drift; chest-smash.js -100 off-screen staging (comment: stranded chests); hero-fx.js:76 invented 0.13/0.9 display stat splits; arc(...,0,7) used as 2π in ~8 places; non-canonical easeOutBack c=1.9.
  • Logic layer is otherwise clean — battle.ts/heroes.ts/economy read their scalars from C.BATTLE/C.HERO_*/C.LEVEL_SCALING. The concentration is in view (Board, FxLayer, HpBar, screens) and VFX.
