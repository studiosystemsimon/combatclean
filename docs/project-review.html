C1Runtime trinket→accessory save-migration shimFixed

migration Hydration inline-remapped slot:"trinket" → "accessory" so pre-rename saves would load. But Combat Clean is a pre-release blank starter with no shipped saves — the only trinket-era blob that could exist is a stale dev artifact, so the shim was defensiveness against a state that can't reach production. Resolved: removed the ternary; hydration now reads slot straight through. (A stale dev save is handled by clearSaved.)

src/game/store/persistence.ts:70 slot: (it as any).slot ← shim removed

The surrounding (it as any) casts are the pre-existing account-item-union style, untouched.

C2GEAR_SLOTS barrel export is now effectively deadInfo

dead-export After the per-class loadout migration, no view/model consumes the flat GEAR_SLOTS list any more — screens iterate the class's resolved slots instead. The definition list is still needed internally (content.ts builds it; GEAR_SLOT_META maps over C.GEAR_SLOTS), but the public barrel re-export has no remaining reader.

src/data/gear.js:5 export const GEAR_SLOTS = C.GEAR_SLOTS; ← no external consumer
Follow-up — optional: drop the barrel re-export (keep the internal C.GEAR_SLOTS that GEAR_SLOT_META needs). Harmless if left.
